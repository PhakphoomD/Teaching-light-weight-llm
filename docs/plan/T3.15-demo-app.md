# T3.15 — Local RAG demo app (the product half of the vision, finally runnable)

- **Phase:** P3-C (code) · **Owner:** ops-engineer + codebase-steward · **Depends on:** ADR-030/033 (WixQA + delivery)
- **Output:** a minimal local chat app under `app/` that anyone can run on commodity hardware

## Objective
A simple, local, private Q&A chat that embodies the project's honest findings: **small model (3B) +
RAG + the delivery fix**, running with zero cloud calls — the thing an SME could actually use.

## Why (hub context)
The vision was "honest research + a product for SMEs". The research is done; the product was never
built. A runnable demo converts the portfolio from "analysed well" to "analysed well AND ships".
The delivery finding (+0.130 free) is the impressive thing to show live.

## Design decisions (locked by the findings — do not drift)
- **Corpus = WixQA** (or another genuine-knowledge-gap KB), NOT MedQuAD. RAG demonstrably helps on
  WixQA (+0.152) and is null on MedQuAD (ADR-027/030) — a demo must show the system *working*, and
  be honest that RAG helps only where a real gap exists.
- **Model = local 3B via Ollama** (`qwen2.5:3b`), the product floor (ADR-015). No cloud.
- **Grounding = the chunk-centred wider window** (ADR-033, the delivery fix) — retrieve, ground on
  the matched chunk with the 2,400-char window, not the article head.
- **Self-refine = an OFF-by-default toggle**, labelled honestly ("~3× cost, ~0 aggregate gain" —
  ADR-032). Show it as an option with its real trade-off, not as a silent default.
- **Show the sources.** The UI displays the retrieved passages it grounded on (trust + honesty; the
  student never sees a gold answer — there is none at inference).

## Steps
1. Streamlit app in `app/` (reuse the `tools/dataset/app.py` pattern): question box → retrieve
   top-k from the WixQA index → build the chunk-centred grounding → 3B answers via Ollama → show
   answer + the source passages + retrieval confidence.
2. A visible toggle: "iterative self-refine (slower, rarely better)" — honest labelling.
3. Config-driven (reuse the six-slot contract where sensible) so the corpus/model can be swapped —
   no hardcoded paths (§0.3).
4. A short `app/README.md`: one-command run, what it does, and the honest caveat (helps where a real
   knowledge gap exists; not a general medical oracle).
5. Capture a screenshot + short GIF for the narrative (T3.17).

## Definition of Done
- `streamlit run app/...` works locally on the 8GB machine, zero cloud calls; answers are grounded
  and cite sources; the self-refine toggle works; README + screenshot/GIF produced.

## Must NOT do
- Don't use MedQuAD as the demo corpus (RAG is null there — a weak, misleading demo). Don't hide the
  self-refine trade-off. Don't expose or require any ground-truth at inference. No hardcoded paths.

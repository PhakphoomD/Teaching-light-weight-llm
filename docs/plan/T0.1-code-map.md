# T0.1 — Code Map (as-built survey of the whole house)

- **Phase:** P0 (read-only) · **Owner:** housekeeping agent · **Depends on:** none
- **Output:** `docs/audit/CODE_MAP.md`

## Objective
Produce a complete map of every tracked source/config file: what it does, who imports it, and a
verdict tag — so the P1 blueprint and P2 demolition (T2.9) work from facts, not guesses.

## Why (hub context)
The project is being renovated ("old house"). Before redesign we need the as-built drawing.
The hub already found ~16% of the Python codebase is dead; this task completes and verifies
that picture file-by-file.

## Read first
- `.claude/rules/structure.md` (canonical layout + junk checklist)
- Output of `git ls-files`

## Steps
1. Enumerate all tracked `*.py`, `*.yml`, `*.md`, `*.json` under `src/`, `tools/`, `scripts/`,
   `config/`, root, `schemas/`, `notebooks/` (skip `data/` contents and `logs/` contents —
   list those dirs as single entries).
2. For each file record: path · line count · one-sentence role · imported-by (grep evidence) ·
   verdict tag: `EXEMPLAR` (pattern to copy) / `ALIVE` / `MESSY` (alive but needs rework) /
   `DEAD` (no importers, no entrypoint) / `MISPLACED`.
3. Build a short import graph of the live core (root runners → src modules).
4. Summarise per-directory: keep / rework / demolish counts.

## Definition of Done
- Every tracked file above appears exactly once with a verdict + evidence.
- A "Demolition candidates" table exists (feeds T2.9) with proof of deadness (0 importers).
- An "Exemplars" section names patterns worth copying.

## Must NOT do
- No edits/deletes/moves of any file (P0 is read-only). No `data/` or `logs/experiments/` writes (guard).

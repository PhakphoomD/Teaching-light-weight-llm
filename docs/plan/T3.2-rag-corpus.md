# T3.2 — Build the RAG Retrieval Corpus + Index

- **Phase:** P3-A (code) · **Owner:** data-engineer · **Depends on:** T3.1
- **Output:** retrieval corpus + FAISS index build tool (a reusable block, not a throwaway) + build report

## Objective
Turn `data/clean/` Diabetes into a retrieval index per the T3.1 architecture: chunk → embed →
index, with the held-out 125 provably excluded.

## Why (hub context)
This is the knowledge source the product actually relies on (Track A showed the model can't
supply it). It must be a reusable tool (the user's Lego-block rule) so swapping domain =
re-point at another `data/clean/*.jsonl`, not rewrite code — the future "product-sales" corpus
reuses this exact block.

## Read first
- `docs/plan/RAG_SPEC.md` (T3.1 architecture — chunking/embedding/index decisions)
- `data/clean/Diabetes_and_Digestive_and_Kidney_Diseases_train.jsonl` (corpus source; n≈506)
- `data/clean/..._heldout.jsonl` (the 125 that must be EXCLUDED) · `tools/dataset/embeddings.py`
  + `src/tlw/memory/` FAISS code (reuse, don't reinvent)

## Steps
1. Build tool under `tools/rag/` (config-driven, like `tools/dataset/`): input jsonl(s) →
   chunk per T3.1 → embed → FAISS index + a passage store (id → text + source metadata).
2. **Held-out exclusion (hard, tested):** assert no held-out question/answer text appears in any
   indexed passage; emit the check result in the build report (§0.2 — retrieval leak = the
   ADR-001 failure in a new costume).
3. Build report: corpus size, chunk count, embedding model + dim, index type, exclusion check,
   a few sample retrievals (query → top-k passages) for eyeballing quality.
4. Reproducible single command (§0.3), tlw python (§0.5); index artifacts land under a
   non-immutable path (NOT `logs/experiments/`), e.g. `models/rag_index/` or `data/processed/`.

## Definition of Done
- One command rebuilds the index from `data/clean/`; build report shows the held-out-exclusion
  check PASS; sample retrievals attached; tool works on a second domain file (generality smoke).

## Must NOT do
- Don't index the held-out split. Don't hand-tune chunking against held-out questions. Don't
  duplicate the FAISS wrapper — reuse `src/tlw/memory`. No hardcoded absolute paths.

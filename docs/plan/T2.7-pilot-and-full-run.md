# T2.7 — Pilot then Full Track-A Run (spend the budget once, correctly)

- **Phase:** P2 (execution) · **Owner:** ops-engineer + qa-engineer · **Depends on:** T2.6
- **Output:** pilot report + full-run outputs (per-arm, per-seed summary.jsonl) + run log

## Objective
Execute the ablation: first a pilot (~25 train-split questions, all 4 arms, 1 seed) to catch
problems cheaply, then — only if the pilot is clean — the full run (held-out 125 × all arms ×
seeds per EVAL_SPEC) within Groq daily caps.

## Why (hub context)
API budget is the scarce resource (70B: 1K req/day, 100K tok/day). A bug discovered mid-full-run
wastes a day's quota and poisons results. Pilot first is non-negotiable.

## Read first
- EVAL_SPEC budget table (T1.4) · `providers.md` rate limits · T2.6 dry-run notes
- `data/clean/` split files (confirm held-out row count = expected 125 before starting)

## Steps
1. **Pilot** on TRAIN questions: run 4 arms × 1 seed × ~25q. Review per-round logs manually:
   feedback quality sane? judge verdicts plausible? arm B truly never calls teacher? token
   spend per question vs budget estimate?
2. Pilot report: go/no-go per checklist; any anomaly → NEEDS-HUB-DECISION, stop before full run.
3. **Full run** (only after go): held-out 125 × 4 arms × seeds from EVAL_SPEC; schedule across
   days if caps require (the plan for this comes from the EVAL_SPEC budget table — follow it);
   record actual token/request consumption.
4. Integrity checks after each arm: row counts, no duplicate question ids, seeds recorded,
   config snapshot present.
5. Archive outputs to the runs dir; NOTHING written into legacy `logs/experiments/`.

## Definition of Done
- Pilot report with explicit go decision · full-run outputs complete for every arm×seed ·
  consumption log vs budget · integrity checklist all green.

## Must NOT do
- Don't look at per-question held-out content and adjust anything mid-run (no peeking/tuning;
  §0.2). Don't re-run failed arms with silently changed settings — any change = new run id +
  note. Don't exceed daily caps by hammering retries.

# T3.8 — Combined Product Eval (LIGHT SPEC — firm up after T3.5 gate)

- **Phase:** P3-B (analysis) · **Owner:** qa-engineer · **Depends on:** T3.7
- **Output:** `docs/PRODUCT_RESULTS.md` + ADR → hub gate for P3-C

## Objective
The final honest product number: does **3B + RAG + LoRA** deliver the domain quality target, and
how close does it get to the 7B / big-model ceiling — on the held-out 125, same judge as Track A.

## Why (hub context)
This is the payoff of the whole project: a small LOCAL model, deep in one domain, for SMEs. It
must be measured with the same honesty as Track A/RAG, or it is just another inflated demo.

## Read first (AFTER building)
- `docs/TRACK_A_RESULTS.md`, `docs/RAG_RESULTS.md` (the baselines to beat) · T3.7 model card
- `src/tlw/analysis`, `EVAL_SPEC.md`, `RAG_SPEC.md` eval protocols (reuse)

## Steps (provisional)
1. Arms: 3B (base), 3B+RAG, 3B+RAG+LoRA, 7B, 7B+RAG, and the big-model reference. Held-out 125 ×
   3 seeds, blind correctness judge (PASS≥4), faithfulness + reference_match diagnostics.
2. Headline deltas with CI: (3B+RAG+LoRA) − (3B+RAG) = LoRA's marginal value; (3B+RAG+LoRA) vs 7B
   = did the small local product reach the ceiling; cost/latency per arm (the SME story).
3. `docs/PRODUCT_RESULTS.md`: methods, table, verdict, limitations; reconcile-numbers; ADR.

## Definition of Done
- Reproducible product results doc; every number traces to a log; ADR with the product verdict
  + a recommendation on P3-C (is it worth a UI / which config ships).

## Must NOT do
- No merged score, no metric shopping, no held-out leakage. State claims narrowly (one domain).
  Don't over-claim "matches the big model" without the CI supporting it.

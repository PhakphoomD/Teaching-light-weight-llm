# T1.1 — Experiment Config Contract v1 (the six slots A–F)

- **Phase:** P1 (docs only) · **Owner:** program-architect · **Depends on:** T0.1

## Objective
Turn the user's slot idea into a formal, written contract in schema.md: one run = one config
file with six slots, every slot resolved through a registry, defaults layered, nothing hardcoded.

## Why (hub context)
The user explicitly asked that this contract live in schema.md "so we don't forget and don't
get messy". The current config already drifted (comment says weights sum differently than the
values; `pass_threshold` hides under `teacher:`). The contract is the backbone of every P2 block
and of future fine-tuning work — swap models/memory/presets by editing YAML only.

## The draft the hub already agreed on (formalize this — do not redesign from scratch)
```yaml
# run.py --config experiments/trackA_armC.yml
student:  { provider: local,  model: qwen2.5:3b }          # A — answerer under test
teacher:  { provider: groq,   model: llama-3.3-70b }       # B — feedback generator (may see GT)
preset:   { student: minimal, teacher: orca }              # C — prompt preset names → PresetRegistry
memory:   { type: faiss, embedding: minilm, top_k: 3 }     # D — type → MemoryRegistry (faiss|rag|none)
params:   { max_rounds: 3, seed: 42 }                      # E — loop params, seeds, arm strategy
eval:     { judge: { provider: groq, model: llama-3.3-70b },  # F — judge + thresholds live HERE,
            mode: blind, pass_threshold: 0.7 }                #    not under teacher
```

## Steps
1. Specify each slot: required/optional keys, types, allowed values, which registry resolves it.
2. Layering rule: `config/base.yml` holds ALL defaults (single source — kills comment-drift);
   experiment files override only what differs; document merge order + `EXPERIMENT_*` env overrides.
3. Validation rules (implemented later in T2.1, specified now): weights sum to 1.0 ± ε;
   judge family ≠ student family (§0.2, families per `providers.md`); unknown keys rejected;
   seed mandatory for experiment runs (§0.3).
4. Naming convention for experiment configs: `experiments/<track><phase>_<arm>_<slug>.yml`.
5. Record the contract via `new-adr` (one ADR: "Config Contract v1").

- ADR logged. No code written.

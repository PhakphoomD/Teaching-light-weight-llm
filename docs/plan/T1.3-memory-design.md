# T1.3 — Honest Memory Design Spec (memory v2)

- **Phase:** P1 (docs only) · **Owner:** program-architect + prompt-engineer · **Depends on:** T0.3, T1.1
- **Output:** new section "Memory v2 contract" in `.claude/rules/schema.md`

## Objective
Specify a memory system that helps the student WITHOUT becoming an answer key: what an episode
stores, what it may never store, how retrieval works, and the `MemoryBackend` interface that
lets us swap FAISS → RAG/sqlite-vec later from config slot D.

## Why (hub context)
Old memory degenerated into storing `"The correct answer is: {GT}"` → the "100%" result was the
system quoting its own answer key (ADR-001). The user's deeper goal remains valid: accumulated
experience should make the small model better. The fix is *what* we store: reusable teaching
notes and domain context, never verbatim reference answers. Inspiration (read, adapt to small
models, don't copy blindly): A-MEM (arXiv 2502.12110) — memories as linked, tagged notes;
"From RAG to Memory"/HippoRAG 2 (arXiv 2502.14802) — memory as non-parametric retrieval store.

## Steps
1. Episode schema v2: id, question_embedding-key, **teaching_note** (strategy/critique — the
   feedback that worked), tags/keywords, links to related episodes (A-MEM style), success stats,
   provenance (which run/arm created it, teacher model).
2. **Forbidden-content rule as schema:** `teaching_note` MUST NOT contain the reference answer
   verbatim or near-verbatim. Specify the guard: similarity(note, ground_truth) threshold +
   substring check at `store()` time → reject + log. (Test lands in T2.5.)
3. Retrieval contract: query → top-k notes above similarity floor, ranked (keep current
   success_rate > score > attempts idea); returned notes are *guidance*, injected only into
   refinement prompts, never as answer text.
4. `MemoryBackend` interface: `store(episode)`, `retrieve(question, k)`, `update_outcome(id, ...)`,
   `stats()` — registry name for slot D (`faiss` | `none` for baseline arms | future `rag`).
5. Lifecycle: when episodes are written (per-arm rules — arms A/B never write; C/D write notes),
   drift control (cap, eviction), and separation *per experiment* (no cross-run contamination —
   each run gets a fresh store unless config says otherwise, §0.3).
6. Record via `new-adr`.

## Definition of Done
- schema.md Memory-v2 section: episode schema, forbidden-content rule, retrieval contract,
  interface, lifecycle. ADR logged.

## Must NOT do
- No implementation (T2.5). Don't design for multi-user/production scale — one honest local
  store first. Don't delete the old memory code or logs.

# T1.4 — Track-A Evaluation Design Spec (the heart of the honest result)

- **Phase:** P1 (docs only) · **Owner:** program-architect + qa-engineer · **Depends on:** T0.3, T1.1
- **Output:** `docs/plan/EVAL_SPEC.md` (+ ADR for the locked decisions)

## Objective
Write the complete measurement protocol for the 4-arm ablation so that the headline number
(C − B) is defensible: metrics, judge setup, arms, data, seeds, statistics, and API budget.

## Why (hub context)
Old eval mixed "correctness" and "looks-like-the-reference" into one hybrid score (~65-75%
reference-proximity) and let GT leak → inflated 25%→83%→100% (ADR-001). Track A exists to
answer ONE question honestly: **does an independent teacher's feedback improve a small student
beyond what self-retry achieves?** Effect = C − B. A small honest number (+5-10%) is the goal;
a suspicious 100% is failure.

## Read first
- ADR-001, ADR-002, ADR-011, ADR-014 · `providers.md` (§0.2 family rule + rate limits)
- `docs/audit/LEAKAGE_CENSUS.md` · `data/clean/` split outputs (train 506 / heldout 125 Diabetes)
- `tools/dataset/judge.py` + `scripts/compare_judges.py` (existing judge evidence, n=8)

## Steps
1. **Arms** (all on the same held-out set, same seeds):
   - A baseline: single-pass, no loop/memory.
   - B self-refine: student critiques itself, no teacher.
   - C blind-teacher: teacher feedback WITHOUT seeing GT.
   - D sighted-teacher: teacher sees GT (label as *leakage ceiling*, not a result).
   Student and eval path see GT in NO arm (§0.2). Memory per T1.3 arm rules.
2. **Two metrics, never merged:** (i) `correctness` — LLM judge verdict, decides pass/fail;
   (ii) `reference_match` — semantic/ROUGE vs reference, diagnostic column only.
3. **Judge design:** family ≠ student family; judge ≠ teacher model if feasible; blind-first
   (judge sees Q + answer, not the reference); define rubric prompt, score scale, parse rules,
   and a small calibration probe (GOOD/WRONG/TRUNCATED sanity set, extend compare_judges.py idea).
4. **Determinism & stats:** seeds (≥3), temperature policy, CI method for pass-rate deltas
   (bootstrap or Wilson), the pre-registered claim: "loop effect = C − B with 95% CI".
5. **Budget:** compute API calls per arm×seed×125q×max_rounds against Groq daily caps
   (70B: 1K req/day, 100K tok/day); choose judge/teacher models accordingly (qwen3-32b has
   500K TPD); schedule runs across days if needed.
6. **NEEDS-USER-DECISION at gate (present both, with recommendation):**
   (a) Track-A student = `qwen2.5:7b-instruct` local (product-relevant, per ADR-014) vs
       `llama3.1:8b` (continuity with ADR-001 baseline) — hub leaning: Qwen, judge = Groq Llama-70B.
   (b) correctness judge blind (no GT — zero leakage) vs GT-comparing-but-independent —
       hub leaning: blind primary, GT-comparing as secondary diagnostic.

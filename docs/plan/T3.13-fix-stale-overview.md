# T3.13 — Retire the stale inflated narrative (§0.1 — MUST before any commit/showcase)

- **Phase:** P3-E hygiene (docs) · **Owner:** qa-engineer · **Depends on:** none (do anytime; independent)
- **Output:** corrected or retired `docs/PROJECT_OVERVIEW_AND_RESULTS.md`

## Objective
`docs/PROJECT_OVERVIEW_AND_RESULTS.md` still tells the OLD inflated story — "25% → 83% → 100%",
"ground-truth memory injection achieving 100% accuracy" (lines 5, 20, 578, 651). This directly
contradicts ADR-024/027/030 and is exactly the narrative the renovation exists to kill. It is a
LIVE §0.1 violation: anyone who opens that file gets a false result.

## Why (hub context)
Honesty over optics (§0.1). A single stale doc claiming 100% can undo the credibility of the
entire honest rebuild — a reviewer who finds it will distrust everything. Must be fixed before the
repo is committed/shown.

## Read first
- `docs/PROJECT_OVERVIEW_AND_RESULTS.md` (the stale claims) · ADR-024, ADR-027, ADR-030
- `docs/TRACK_A_RESULTS.md`, `RAG_RESULTS.md` (the honest numbers that replace them)

## Steps
1. Decide (small NEEDS-HUB call if unsure): rewrite it to the honest findings, OR replace it with
   a short pointer to `TRACK_A_RESULTS.md` / `RAG_RESULTS.md` / (T3.12) `RAG_LAW.md` and archive
   the old file to `docs/archive/` with a header "SUPERSEDED — inflated pre-renovation numbers".
2. Ensure NO doc in the repo still asserts 25→83→100 as a result (grep to confirm zero hits

3. Run `reconcile-numbers` over `docs/` as the final check.

- No live doc claims the inflated numbers; the overview either states the honest result or points

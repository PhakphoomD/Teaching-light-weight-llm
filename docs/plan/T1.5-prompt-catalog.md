# T1.5 — Prompt Catalog: curate the graveyard into a preset registry

- **Phase:** P1 (docs + prompt file reorg only) · **Owner:** prompt-engineer · **Depends on:** T1.1
- **Output:** `docs/plan/PROMPT_CATALOG.md` + proposal for the new preset file layout

## Objective
Reduce ~38 accumulated prompt variants (13 student + 25 teacher in `config/prompts_config.yml`)
to a small named preset catalog (slot C of the Config Contract), with a written verdict for
every variant: KEEP (preset name) / ARCHIVE (why it lost).

## Why (hub context)
The prompt file is an experiment graveyard — every trial was kept, nobody knows which matter.
The user called this "มั่ว" and he's right. Slot C (`preset: {student: minimal, teacher: orca}`)
needs a curated registry. Evidence so far: ORCA-style teacher feedback beat principle-style and
simple-CoT (Phase-2, report Table 12); minimal student prompts were the design intent for small
models (3-4 lines, `src/simplified/student.py` docstring).

## Read first
- `config/prompts_config.yml` (all variants) · `src/utils/prompt_loader.py` (how they're loaded)
- `PROMPT_STRATEGY_MAP` in `simplified_teaching_loop.py:59-66`
- Phase-2 results: `logs/experiments/phase2/summary.jsonl` (which style won, real numbers)
- `docs/audit/LEAKAGE_CENSUS.md` (templates containing `{ground_truth}` → student presets must die)

## Steps
1. Inventory every variant: name, role (student-first/student-refine/teacher-feedback/judge),
   used-by evidence (grep configs + code), experimental evidence if any (phase logs).
2. Verdict per variant. Expected survivors ≈ 6-8: student minimal first/refine, self-critique
   pair (needed for arm B!), teacher orca (blind + sighted versions per T1.4), judge prompts
   (from T1.4 spec). Note: arm B (self-refine) needs a *student self-critique* preset that may
   not exist yet — spec it if missing.
3. Anti-leakage check: any KEEP preset visible to the student must have no `{ground_truth}`
   placeholder. Teacher-sighted presets carry an explicit `# GT-VISIBLE: teacher-only` header.
4. Propose target layout: e.g. `config/prompts/` split by role, names matching PresetRegistry
   keys, `archive/prompts_config_legacy.yml` for the losers (moved in T2.x, not now).
5. Naming convention: `<role>.<style>.<variant>` (e.g. `student.minimal.first`).

## Definition of Done
- Catalog doc: full inventory table + verdicts + evidence; survivor list with final names;
  missing-preset gaps flagged (self-critique, blind-teacher); target file layout proposal.

## Must NOT do
- Don't edit/delete `config/prompts_config.yml` yet (runtime still reads it — moves happen in P2).
- Don't write new prompt text beyond skeletons for missing presets (final wording lands with
  tests in T2.3/T2.4).

# T3.4 — Grounded-QA Eval Block (faithfulness + blind correctness)

- **Phase:** P3-A (code) · **Owner:** qa-engineer · **Depends on:** T3.1, T2.3 (existing judge)
- **Output:** grounded-eval extension to the evaluation block + faithfulness metric + tests

## Objective
Extend the evaluation block so RAG runs are judged on **grounded correctness** (the same blind
correctness judge as Track A, for comparability) plus a **faithfulness** diagnostic — is the
answer actually supported by the retrieved passages, or hallucinated?

## Why (hub context)
RAG's whole promise is fewer hallucinations via grounding. But "grounded" must not collapse into
reference-phrase-matching (ADR-001 trap). Keep correctness as the headline (comparable to
Track A's 0.821/0.912/…) and add faithfulness as a separate diagnostic — never merged (ADR-019).

## Read first
- `docs/plan/RAG_SPEC.md` §eval (T3.1) · `src/tlw/evaluation/` (judge to reuse) · `EVAL_SPEC.md`
  (blind judge rubric, PASS≥4) · `src/tlw/analysis/` (delta+CI machinery to reuse)

## Steps
1. Reuse the Track-A blind correctness judge unchanged (comparability): question + answer →
   0–4, PASS iff ≥4, judge family ≠ student family, temp 0.
2. Add **faithfulness** diagnostic per the metric T3.1 chose (proposed default: RAGAS-style
   groundedness — Es et al. 2023, arXiv 2309.15217): given (answer, retrieved passages), judge
   whether each claim is supported. Independent judge, no gold answer in its prompt. Reported as
   its own column; NOT part of pass/fail.
3. Keep `reference_match` (semantic/ROUGE) as the existing diagnostic too — so we can show, again,
   whether it tracks correctness or misleads.
4. Extend `src/tlw/analysis` to emit the RAG arms table + `(3B+RAG)−3B` delta with CI, alongside
   faithfulness/reference_match columns.
5. Tests: faithfulness parser edge cases; a hallucinated answer scores low faithfulness; a
   grounded answer scores high; correctness path still has zero gold-answer exposure.

## Definition of Done
- Grounded eval runs; produces correctness (headline) + faithfulness + reference_match as three
  separate columns; analysis emits the RAG delta with CI; tests pass.

## Must NOT do
- No merged score. Faithfulness/similarity never gate pass/fail. Don't fork a second judge model
  for correctness (reuse Track-A's, or the comparison is meaningless).

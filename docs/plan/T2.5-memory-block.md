# T2.5 — Memory Block v2 (honest memory with a leakage tripwire)

- **Phase:** P2 (code) · **Owner:** data-engineer · **Depends on:** T2.2, Memory spec (T1.3)
- **Output:** `faiss` + `none` MemoryBackend implementations + leakage-assertion tests

## Objective
Implement the T1.3 memory contract: episodes store teaching notes (never answers), retrieval
returns guidance, and `store()` REFUSES content that smells like the reference answer.

## Why (hub context)
The old memory became an answer key (`"The correct answer is: ..."` episodes → fake 100%).
v2 makes that structurally impossible: the tripwire raises at store time, so no future
experiment can silently regress into leakage.

## Read first
- schema.md "Memory v2 contract" (T1.3 — the spec) · `docs/audit/LEAKAGE_CENSUS.md` MEMORY-STORED items
- `src/simplified/memory.py` (salvage: FAISS handling, ranking, JSONL persistence — rewrite lean)

## Steps
1. `FaissMemory(MemoryBackend)` per contract: episode schema v2, store/retrieve/update_outcome,
   per-run isolated storage path (from config; fresh store per experiment unless configured).
2. **Tripwire:** `store()` receives the episode AND the reference answer for the question;
   reject if note ⊇ reference substring or similarity(note, reference) > threshold from T1.3;
   rejection is logged loudly. Test: attempt to store `"The correct answer is: {ref}"` → raises.
3. `NoneMemory` (for arms A/B and baselines): trivially empty, satisfies the interface.
4. Retrieval ranking per contract (success_rate → score → attempts, keep the good legacy idea);
   returned notes marked `guidance` — the loop injects them only into refinement prompts.
5. Tests: round-trip persistence, ranking order, tripwire, per-run isolation.

## Definition of Done
- Both backends registered + tests pass (evidence: test output). Tripwire test demonstrates the
  exact legacy failure mode now raises.

## Must NOT do

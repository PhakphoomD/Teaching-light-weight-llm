# T3.7 — QLoRA Fine-Tune the 3B (LIGHT SPEC — firm up after T3.5 gate)

- **Phase:** P3-B (code/training) · **Owner:** ops-engineer · **Depends on:** T3.6
- **Output:** LoRA adapter under `models/` + training run log + repro command

## Objective
QLoRA 4-bit fine-tune the product 3B on the T3.6 data on the local RTX 4060 8GB, producing a
small style/format adapter — not a knowledge dump (knowledge stays in RAG).

## Why (hub context)
Bakes the self-refine style into weights so the deployed model is good on the first pass without
the loop. Must run on the user's own 8GB GPU (the "runs on any PC" promise) — QLoRA 4-bit makes
a 3B trainable there (CLAUDE.md hardware note: QLoRA ok for 7-8B, comfortable at 1-3B).

## Read first (AFTER the T3.5 gate)
- `docs/RAG_RESULTS.md` gate outcome (how much LoRA is expected to add) · T3.6 data card
- CLAUDE.md hardware/env · `providers.md` (the base 3B model id) · `structure.md` v2 `models/` placement

## Steps (provisional)
1. Env: QLoRA stack (bitsandbytes/peft/transformers) in the tlw conda env (§0.5); verify 4-bit
   loads the 3B within 8GB VRAM before a full run.
2. Train a small LoRA adapter (conservative rank/epochs — LIMA-scale, avoid overfitting 1k pairs);
   seed everything (§0.3); log loss + a few sample generations.
3. Save adapter + training config + git commit to `models/<name>/`; write a model card.
4. Smoke test: load base+adapter locally, generate on a few TRAIN questions, eyeball style change.

## Definition of Done
- Adapter saved + reproducible train command + model card; fits and runs on 8GB; smoke
  generations attached. NOT evaluated for quality here (that is T3.8).

## Must NOT do
- Don't train on held-out. Don't chase a big adapter / many epochs (overfitting a small set).
  Don't put knowledge-cramming as the goal — that failed in Track A and is RAG's job. Adapter
  goes in `models/` (git-ignored large), never committed as a blob.

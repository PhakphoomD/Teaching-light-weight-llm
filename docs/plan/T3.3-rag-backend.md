# T3.3 — RAG Backend (slot D `type: rag`) + grounding into the answer prompt

- **Phase:** P3-A (code) · **Owner:** codebase-steward + data-engineer · **Depends on:** T3.2
- **Output:** `rag` MemoryBackend registered + grounding wiring in the loop + tests

## Objective
Implement the reserved slot-D `type: rag` backend so a run can retrieve domain passages and the
loop injects them as **grounding context** — turning `type: none` (Track-A) into `type: rag`
by config alone.

## Why (hub context)
The seam was designed for exactly this (`src/tlw/registries.py:16` leaves `rag` unregistered,
failing loud until now). Building it here proves the plugin architecture the user wanted:
add knowledge to the product by changing one YAML line, no runner surgery.

## Read first
- `docs/plan/RAG_SPEC.md` (T3.1) · `schema.md` slot D + `MemoryBackend` seam
- `src/tlw/registries.py` (register pattern) · `src/tlw/memory/` (faiss backend to mirror)
- `src/tlw/loop/core.py` (where grounding context is injected; and `assert_gt_free` — grounding
  must pass through it)

## Steps
1. `RagMemory(MemoryBackend)` reading the T3.2 index: `retrieve(query, top_k)` → passages;
   `store`/`update_outcome` = no-op (corpus is read-only knowledge, not run-written notes);
   register `@register("rag")` in MemoryRegistry.
2. Loop wiring: retrieved passages enter the **answer prompt** as cited grounding context
   ("Use these references: …"). PROPOSED (confirm against T3.1's RAG_SPEC): inject grounding at
   the FIRST attempt — rationale = grounding is knowledge, useful up front, unlike teaching notes
   which were refinement-only. If T3.1 decided otherwise, follow RAG_SPEC.
3. **Leakage guard extends to grounding:** `assert_gt_free` (or its equivalent) must confirm no
   retrieved passage equals/contains the held-out gold answer for the question under test;
   test this with a red-team case.
4. Tests (mocked/offline where possible): `rag` resolves from config; retrieve returns passages;
   grounding text appears in the student prompt; leak guard trips on a planted gold-answer passage.

## Definition of Done
- `memory: {type: rag}` runs end-to-end via the existing runner (no runner changes beyond seam
  use); tests pass; leak guard demonstrated. Arms A/B still work with `type: none` (no regression).

## Must NOT do
- Don't let grounding inject the gold answer. Don't special-case the runner for RAG (must flow
  through the seam). Don't break the V8 arm×memory validation (RAG runs are their own arms/config).

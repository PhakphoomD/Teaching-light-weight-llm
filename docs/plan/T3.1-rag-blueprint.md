# T3.1 — RAG Blueprint + Grounded-QA Eval Design (paper only)

- **Phase:** P3-A (docs only) · **Owner:** program-architect + qa-engineer · **Depends on:** ADR-024 (Track-A done)
- **Output:** `docs/plan/RAG_SPEC.md` + schema.md slot-D `rag` details + ADR

## Objective
Design, on paper, (1) the retrieval architecture that plugs into Config Contract slot D as
`type: rag`, and (2) the grounded-QA evaluation protocol — before any RAG code is written.

## Why (hub context)
Track A proved knowledge does NOT come from the loop (C−B≈0, ADR-024); it must come from RAG
(Ovadia et al. 2024, EMNLP, "Fine-Tuning or Retrieval?", aclanthology 2024.emnlp-main.15 —
RAG > fine-tuning for factual knowledge). But RAG has its own leakage/honesty traps: retrieved text could contain the
held-out gold answer, and "grounded" can silently collapse back into reference-phrase-matching
(the ADR-001 trap). Design the honest measurement first, same discipline as T1.4.

## Read first
- `docs/TRACK_A_RESULTS.md` + ADR-024 · `docs/plan/EVAL_SPEC.md` (the honest-eval template to mirror)
- `schema.md` Config Contract slot D + Memory v2 (the seam `rag` must satisfy)
- `data/clean/..._readiness_rag.json` (corpus readiness) · `src/tlw/evaluation/` (existing judge to extend)

## Steps
1. **Retrieval architecture (paper):** chunking unit (per Q–A record vs sub-chunk), embedding
   model (reuse MiniLM or justify a change), retriever (FAISS top-k; reuse `src/tlw/memory`
   FAISS code), top-k + similarity floor, how retrieved passages enter the answer prompt as
   **grounding context** (cited passages, never "the answer is …").
2. **Slot-D `rag` contract:** how `type: rag` differs from `faiss` (corpus-backed retrieval vs
   run-local teaching notes); which slot-D keys it uses; that it satisfies the same
   `MemoryBackend`/retriever seam so the runner is unchanged.
3. **Grounded-QA eval protocol** (mirror EVAL_SPEC): primary = **blind correctness** (same
   independent judge, PASS iff score≥4) so RAG numbers are comparable to Track A; PLUS a
   **faithfulness/groundedness** diagnostic (is the answer supported by the retrieved passages?).
   T3.1 DECIDES the faithfulness metric — proposed default = a RAGAS-style LLM-judged groundedness
   ratio (Es et al. 2023, arXiv 2309.15217; ground-truth-free, so §0.2-safe, judged by our
   existing judge). Independent judge, no gold-answer leak into the student path. Diagnostic only.
4. **Pre-registered RAG headline:** `pass_rate(3B+RAG) − pass_rate(3B)` with 95% paired
   cluster-bootstrap CI (same machinery as `src/tlw/analysis`); arms = {3B, 3B+RAG, 7B, 7B+RAG}.
5. **Anti-leak rule for retrieval:** the retrieval corpus is the TRAIN split only; the held-out
   125 must never be in the index (a retrieved chunk = the gold answer would be leakage). State
   this as a hard rule T3.2/T3.4 enforce.
6. ADR: "RAG architecture + grounded-eval protocol".

## Definition of Done
- RAG_SPEC.md: architecture, slot-D `rag` contract, eval protocol, pre-registered headline,
  anti-leak rules, budget (local student+judge = free; embedding = local). ADR logged. No code.

## Must NOT do
- Don't implement anything. Don't let faithfulness/semantic-similarity become the pass gate
  (correctness judge decides; §0.1/ADR-019). Don't put held-out data in the retrieval corpus.

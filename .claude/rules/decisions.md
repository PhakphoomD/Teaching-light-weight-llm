## ADR-033 — PROVEN: RAG's bottleneck is evidence delivery, not the RAG concept — the unified law (T3.12/T3.14) (2026-08-06) · Proposed
**Context:** closes P3-E. ADR-030 asserted "RAG helps iff the retrieved passage holds the answer"; ADR-031 set out to *prove* it via a retriever dose-response; ADR-032 added the never-run Loop+RAG arm. T3.9–T3.11 delivered the proof; T3.14 then found the assertion was **incomplete** — retrieval being correct does not mean the answer reaches the model.
**Decision (the law, in final form):** RAG's effect is gated by a **three-stage pipeline, each independently measured**: (1) **retrieval** — is the answer-bearing doc found? hit-rate 0.550→0.665 via chunking+BGE (T3.10, offline ladder, 7 variants); (2) **delivery** — does the answer text reach the prompt? in-context answer-coverage 0.412→0.655 via a chunk-centred 2,400-char window (T3.14 S1); (3) **extraction** — does the model use what it sees? extraction ratio **88%→61%** = the model now leaves ~39% of in-context answer content unused (the new, unsolved bottleneck). **Proof of (1):** pass tracks hit-rate monotonically (0.163→0.315→0.340) while **P(pass|gold retrieved) stays invariant at 0.400→0.411** — the retriever changes how OFTEN the answer is found, not its value when found; a mixture model built from those conditionals predicts both points (0.315 exact, 0.340 vs 0.337 predicted). **Proof of (2):** holding retrieval byte-identical and changing ONLY the grounding window moved **aggregate pass@≥3 0.340→0.470 (+0.130 [+0.072,+0.188], McNemar p=3.5e-08)** — and the "0.400 model ceiling" rose to 0.534, so it was never a model ceiling. **Delivery outweighed retrieval as a lever: +0.130 vs +0.025, at zero inference cost.** **Loop+RAG (T3.14 S2) does NOT compound:** grounded self-refine raises reference-coverage +0.031 [+0.018,+0.047] and extraction 63%→68%, but pass@≥3 is flat/negative (0.571→0.556, p=0.77) — the ADR-027 tug-of-war replicated for iteration (helps score-0/1 by +0.35, damages score-3 by −0.11, and 57% were already at score 3). **Selective application is the unlock, and the 3B cannot self-gate:** oracle 0.609 (+0.038) vs blind self-assessment gate 0.571 (+0.000); the model called its own answer "complete" 59% of the time including when wrong — the SECOND replication of the selective-RAG result (ADR-027 oracle +9.9pt, cheap gates fail) → **the missing component is a reliable gate, not a better intervention** (consistent with Huang 2310.01798).
**Implication (product):** verify a knowledge gap with a no-RAG baseline BEFORE indexing; spend first effort on delivery not the retriever; ground on the matched chunk, not the doc head; do NOT ship always-on self-refine (~3× cost, 0 gain) or blanket gold-SFT (−0.292); target "correct" (PASS≥3) not "expert-complete" (structurally unreachable — the full source article holds only ~72% of the reference's content). Write-up = `docs/RAG_LAW.md`. Supersedes nothing; completes ADR-030/031/032.
**Evidence:** `docs/{RAG_LAW,WIXQA_RESULTS,RAG_RESULTS,TRACK_A_RESULTS,PRODUCT_RESULTS}.md`; runs `runs_wixqa/` (T3.9 3-seed 600 replicates; T3.11 600; T3.14 S1 600; S2 pilot 133), `data/rag/retriever_ladder/{hitrate,grounding}_table.json`; tools `scripts/wixqa_{run3seed,judge,analyze,retriever_ladder,run3seed_retriever,dose_analyze,grounding_ladder,grounding_compare,selfrefine,repair_empty}.py`. **Honesty notes:** T3.11's aggregate retriever effect is n.s. (+0.014, p=0.6 — the proof is the pattern, not the jump); S2 is single-seed/subset (stopped by the pre-registered gate); 5 crash-emptied records were regenerated pre-judging (`repaired: true`). Two pre-registered predictions were wrong (S1 predicted ~0.36, actual 0.470; S2 predicted +3pt, actual −1.5pt) — both from over-trusting a confounded observational correlation. See [[wixqa-rag-positive-result]], [[rag-heterogeneity-finding]].

## ADR-030 — WixQA verdict: RAG WORKS when a real knowledge gap exists (+13pt, causally proven to be the retrieved data) — the honest mirror image of the MedQuAD null (2026-07-24) · Proposed
**Context:** ADR-027/029 proved RAG can't help on MedQuAD because that testbed has NO fillable gap (3B already knows the definitional facts; a leak-free corpus can't hold the specific held-out answer). To test the OTHER half of ADR-003's thesis — *does RAG add knowledge when the model genuinely lacks it?* — moved to a second, gap-heavy testbed matching the SME product vision: **WixQA** (Wix.com customer-support KB, HF `Wix/WixQA`, MIT license) — **6,221 real help-center articles** + **200 expert-written QA** (`data/wixqa/`). This is the RIGHT RAG setup and NOT leakage: the 3B has zero parametric knowledge of Wix's proprietary product, and the KB is the LEGITIMATE source (grounding on the source article is intended; the expert answer is distilled FROM it) — so NO anti-leak scrub, unlike single-source MedQuAD where corpus==answer. Student=`qwen2.5:3b` local (blind — never sees gold), judge=Groq `llama-3.1-8b-instant` in **reference-comparing** mode (a `gt_comparing` judge, legal for closed-domain: only the JUDGE sees gold to score, §0.2 preserved), PASS≥3 (correct) as the headline metric (PASS≥4 "complete" is near-0 for a 3B + one article — wrong metric here). Standalone scripts (`scripts/wixqa_{baseline,build_index,rag}.py`), doc-retrieval (embed article title+contents, retrieve by question, ground on contents), seed 42.
**Decision (finding):** **PRECONDITION first (de-risk):** 3B no-RAG baseline = **pass@≥3 0.175 / pass@≥4 0.000 / mean 1.77** (dist {0:13,1:55,2:97,3:35} — not one complete answer) vs MedQuAD's 0.86 → massive gap confirmed → greenlit the index. **HEADLINE:** 3B+RAG = **pass@≥3 0.305 (+13pt, +74% rel), McNemar p=0.0026, fixed 48 / broke 22, net +26** → first POSITIVE RAG number in the project. **CAUSAL PROOF it's the data:** split RAG by whether the gold KB article was retrieved — gold RETRIEVED (n=110): 0.136→**0.409** (+27pt, ×3); gold MISSED (n=90): 0.222→**0.178** (−4pt, the SAME distraction tug-of-war as MedQuAD); 75% of fixed questions (36/48) had gold retrieved. Same model/prompt/judge — the ONLY difference between +27pt and −4pt is whether the retrieved DATA held the answer → the lift IS the data.
**Implication:** completes the honest RAG story with a **unified law across both testbeds — RAG helps iff the retrieved passage actually contains the answer**: MedQuAD (answer never retrievable) → null; WixQA gold-missed → −4pt; WixQA gold-retrieved → +27pt. RAG's real bottleneck is **retrieval quality**, not the RAG concept. Product lesson: RAG is worth it for an SME whose private docs hold knowledge the base model lacks — and the ROI is gated by the retriever. **2-testbed framing (user's design):** MedQuAD tests the MODEL (capability ceiling; proves loop/RAG/LoRA add nothing when saturated); WixQA tests RAG+loop where a gap exists. **Limits (§0.1):** retrieval hit-rate = **55%** (110/200) is the ceiling capping the aggregate — a better retriever (article chunking, encoder > MiniLM, hybrid BM25+dense) would lift the aggregate toward 0.409; single seed = directional (the causal split is within-run, so seed-robust; a formal write-up needs 3 seeds). TechQA queued as a harder/specific harden.
**Evidence:** `runs_wixqa/{baseline_norag,rag_top3}.jsonl` (200 each, seed 42, judge fb=0); numbers computed live by paired join on `idx`; index `data/rag/wixqa_kb/manifest.json` (6,221 articles, `anti_leak: none`); baseline de-risk n=15 smoke (0/15 pass@≥4) then n=200; WixQA paper arXiv 2505.08643. See [[wixqa-rag-positive-result]], [[rag-heterogeneity-finding]].

## ADR-028 — LoRA verdict: naive gold-SFT HURTS the 3B (−29pt) — style transfer succeeds but conflicts with the completeness objective (2026-07-23) · Proposed
**Context:** T3.6-3.8 (P3-B LoRA sub-track). Recipe PIVOTED from the spec's loop-factory (self-refine doesn't engage on the near-ceiling train set — T3.6 smoke 5/5 round-1; RAG hurts — ADR-027) to **standard gold-SFT**: 506 (TRAIN question → TRAIN gold NIH answer) pairs. Each for an honest mechanistic reason. Value lives on the **hard tail** (RAG reliability recovery), not the saturated average. Product lesson: don't blanket-fine-tune on reference answers; a strong instruct base is already good, and naive SFT trades completeness for brevity. Better recipes untested (distill a model with the DESIRED complete style; mix general data to prevent forgetting; fewer epochs/lower LR; DPO on completeness).

## ADR-027 — RAG verdict: no NET effect on a 3B, but a real tug-of-war (helps hard, hurts easy) → RAG must be selective (2026-07-16) · Proposed
**Context:** T3.5 headline pair (3B vs 3B+RAG) on the pre-registered 125 held-out Diabetes × 3 seeds {13,42,123}, single-pass (arm A), student `qwen2.5:3b` local, judge Groq `llama-3.1-8b-instant` blind PASS=score≥4 — the SAME judge+bar as the Track-A full run (comparability), 100% Groq (0 fallbacks). 3B baseline REUSED from `trackA_full_armA` (identical config), copied into `runs_rag/` to avoid conflation with the mixed `runs/` dir. 7B/7B+RAG ceiling arms deferred (user chose the ~4h headline path).
**Decision (finding):** **3B+RAG − 3B = −0.005, 95% CI [−0.067, +0.056], McNemar p = 0.91 → NO net effect.** But the null hides a **tug-of-war**: RAG BROKE 39 question-seed pairs (35/39 on questions the baseline passed in ALL seeds = easy → distraction) and FIXED 37 (0 on easy; all on baseline-failed, concentrated on the hardest — 15 on the all-3-fail set ≈ 38% recovery, independently reproduced by a hard-subset probe 5/13). Mechanism: MiniLM retrieval is disease-name-dominated so "treatments for X" retrieves "symptoms of X" (right topic, wrong aspect) → grounding distracts the 3B off its already-correct answer on easy Qs, while supplying the missing fact on hard Qs. A "hardened" grounding prompt (ignore-irrelevant-passages) BACKFIRED (0.80→0.56 — 3B fixates/hedges) → reverted to simple v1; the effect is structural (near-ceiling baseline + small-model distractibility), not a wording problem.
**7B ceiling pair (completed 2026-07-21, clean single Groq judge after a cap-exhaustion re-judge):** 7B 0.904 / 7B+RAG 0.835 → **7B+RAG − 7B = −0.069, 95% CI [−0.120, −0.019], McNemar p=0.0004 (fixed 13 / broke 39) → RAG SIGNIFICANTLY HURTS the 7B**, and more than the 3B. And **3B+RAG (0.816) < plain 7B (0.904)** (−0.088 [−0.136,−0.043]) → retrieval CANNOT lift a 3B to a 7B's level. Mechanism = the same tug-of-war scaled by base strength: a stronger model has FEWER knowledge gaps to fill (7B fails ~10% vs 3B ~18%) but the same distraction tax on the easy majority → the better the model, the more distraction dominates repair. Both RAG_SPEC §3 secondary questions answer NO.
**Implication (P3-B):** do NOT ship a naive always-on RAG layer — it won't move the aggregate and HURTS a stronger model. RAG's honest role is **targeted knowledge repair**: gate retrieval on model uncertainty / retrieval confidence (selective RAG), and/or use a better domain-aware retriever; the eval that matters is the **hard tail**, not the near-saturated average. ## ADR-026 — RAG architecture + grounded-QA eval protocol (T3.1, paper) (2026-07-16) · Proposed
**Context:** T3.1 (first P3-A task, docs-only) designs, on paper, the retrieval that plugs into Config Contract slot D as `type: rag`, and the honest eval that measures it — before any RAG code (T3.2+). Track A proved the loop adds no knowledge (C−B=+0.003, p=1.00, ADR-024); ADR-025 chose RAG as the knowledge source (Ovadia 2024, RAG>FT for facts). RAG brings two new honesty traps: a retrieved passage could BE the held-out gold answer (ADR-001 redux), and "grounded" can silently collapse into reference-phrase-matching.
**Decision:** (1) **Retrieval architecture** — corpus = Diabetes TRAIN split only (506 recs); one passage per cleaned record, embedded/searched by **question** (return the matched record's **answer** as the grounding passage); reuse **MiniLM** encoder + **FAISS IndexFlatIP** (same construction as `src/tlw/memory/faiss_backend.py`); top_k 3, similarity floor **0.35** (deliberately lower than memory's 0.75 — RAG wants related context, not a near-exact twin); passages injected as a labelled REFERENCE-CONTEXT block at the **first answer attempt** ("evidence, not the answer"), never "the answer is…". (2) **Slot-D `rag` contract** — third MemoryBackend impl, same seam so runner unchanged, but corpus-backed + read-only: `store()` is a no-op, `retrieve()` returns passages, injection reaches round 1 (unlike memory notes = refinement-only); adds `corpus_path` + `max_passage_words` keys. (3) **Grounded-QA eval** — primary = **blind correctness reused verbatim from Track A** (`BlindJudge`, PASS iff score≥4) so RAG numbers are comparable; faithfulness metric **DECIDED = RAGAS-style LLM-judged groundedness ratio** (Es 2023, arXiv 2309.15217; GT-free → §0.2-safe; a NEW judge mode, not the unbuilt `gt_comparing`) as a **diagnostic column only, never the pass gate**; `reference_match` kept as diagnostic + leakage smell-test. No weighted fusion (weights stay `{blind_score:1.0}`). (4) **Pre-registered headline** = pass_rate(3B+RAG) − pass_rate(3B) with 95% paired cluster-bootstrap CI + McNemar + Wilson (reuse `src/tlw/analysis/stats.py`); arms {3B, 3B+RAG, 7B, 7B+RAG}, single-pass (retrieval is the only variable; RAG+self-refine is a labelled secondary, not the headline). (5) **Anti-leak (hard rules for T3.2–T3.4; STRENGTHENED 2026-07-16 after the first real run):** RAG-L1 corpus = TRAIN only + manifest with zero held-out ids; RAG-L2a ≥0.90-cosine near-dup scrub; **RAG-L2b verbatim-block scrub (NEW)** — drop any train record sharing ≥8 contiguous 12-token shingles with any held-out answer, because whole-answer cosine is BLIND to templated leaks (MedQuAD "What to do for X?" reuses one NIH template across GI diseases: Crohn's vs Ulcerative Colitis share ~100% verbatim text at only ~0.76 cosine, and 16% of held-out Qs retrieved such a passage); **RAG-L3 = run-time per-passage FILTER (not whole-run abort)** — `grounding_block` drops+counts any retrieved passage still sharing a ≥12-token gold shingle (the residual innocent case: same-topic passages share one definitional sentence with gold), grounds on survivors, reports `grounding_filtered_total` (§0.1); `assert_gt_free` stays the final whole-prompt backstop. slot-D `corpus_path` held-out denylist (V6 analogue). Rationale for filter-not-abort: on-domain RAG will routinely surface passages sharing a definition with the gold answer without being the answer; aborting would make the ablation impossible, filtering keeps the student gold-free and biases conservatively AGAINST RAG. (6) Budget ≈ **free** — students + judge + embedding all local, ~2h GPU, $0 cloud required. **NEEDS-HUB (small):** whether T3.5 adds a labelled 3B+RAG+self-refine secondary arm; V8 needs a one-line exemption so `type: rag` is allowed on arms A/B (read-only corpus ≠ accumulating store).
**Evidence:** `docs/plan/RAG_SPEC.md` (full spec); reuse points cited live — `src/tlw/memory/faiss_backend.py:27-28,119,304-305` (MiniLM+FAISS IP), `src/tlw/evaluation/judge.py:9-11,128,161` (blind by construction), `src/tlw/evaluation/diagnostics.py:88` (reference_match), `src/tlw/analysis/stats.py:41,88,168` (stats machinery), `src/tlw/loop/core.py:36` (assert_gt_free guard), `src/tlw/registries.py:16` (rag reserved-unregistered); corpus `data/clean/…_train.jsonl` (506, `wc -l`) READY 93.4 (`…_readiness_rag.md:2`), uniqueness 97.3 (`:6`); RAGAS arXiv 2309.15217, Ovadia EMNLP 2024.

**Decision:** add an enforcement layer: `.claude/settings.json` (permission denies: edit raw data / `logs/experiments/` / `.env`; allowlist for git-read + tlw python) + `.claude/hooks/guard.py` (PreToolUse: blocks bare `python`/`pip` in command position and writes into immutable/evidence dirs, exit 2 with the rule cited) + `.claude/skills/` (`run-pipeline`, `reconcile-numbers`, `new-adr`). Guard is deliberately narrow (command-position regex) — prefers rare misses over false blocks.
**Evidence:** hooks/permissions schema from code.claude.com/docs (hooks, settings); guard verified 12/12 scenarios via `scratchpad/test_guard.py` run with tlw python.

## ADR-011 — Judge model selection (2026-07-12) · Proposed
**Context:** D4 (dataset answer quality) and Phase-A eval need an LLM judge; §0.2 wants independence from the Llama student/teacher.
**Evidence** (`scripts/compare_judges.py`, n=8 discrimination probe): Groq Llama-3.3-70B vs local Qwen2.5-7B judge **nearly identically** — inter-judge |diff| 0.10; discrimination GOOD−WRONG +0.70 vs +0.68, GOOD−TRUNC +0.40 vs +0.44. Groq ~42× faster (0.07 vs 2.99 s/call).
**Recommendation:** use **local Qwen2.5-7B (Ollama)** as the *measure/eval* judge — different family from Llama (§0.2), free, private, and it judges as well as the 70B. Use **Groq** for throughput-bound *dataset* scoring (D4 over full sets) where independence isn't required. Small sample (n=8) — directional; confirm before locking.

## ADR-008 — Agent design standard (2026-07-12) · Accepted
**Context:** first-pass agents were too generic (no output contract, no evidence rule).
**Decision:** every agent uses the skeleton Identity / Must-read / Procedure / Checklist(DoD) / Output-contract / Guardrails. Three output archetypes: **R** (Review: VERDICT+FINDINGS[BLOCKER/MAJOR/MINOR]+NOT VERIFIED+EVIDENCE LOG) for auditors; **B** (Build: SUMMARY/CHANGES/EVIDENCE/VERIFICATION/DECISIONS/NOT-DONE) for makers; **P** (Plan) for the coordinator. Rules gain `§0` anchors + ADR IDs so findings cite authority.
**Evidence:** Anthropic context-engineering ("right altitude"), prompting best practices (role, output contract), 2500-config analysis (commands early).

## ADR-001 — Original results are inflated; model is not the bottleneck (2026-07-10) · Accepted
Reported "25%→83%" ≠ committed logs (33%→84%). Metric measures similarity to a noisy reference, not correctness; teacher sees GT every round (guided imitation); "100%" (P6C) = memorization. Baseline Llama-3.1-8B already answers well. Root cause = loop design + evaluation + dataset quality. TinyLlama fails on capability floor, not concept.
